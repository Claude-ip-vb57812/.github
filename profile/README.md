<p>白名单看着只是一个勾选项，实际有六个参数：授权类型、绑定对象、生效延迟、条数上限、回收方式、日志留存。这六个参数里任何一个设错，表现都是「配了但不生效」或者「生效了但换人之后立刻断」。团队协作最容易踩的坑就在这里：换人接手时不想整号重搭，结果改了一堆配置还不如直接加一条授权。这篇按参数说明书的方式逐项写清每一项的取值范围、默认行为和误配症状，最后给一个换人接手的标准操作顺序。</p>

<h2>一、白名单有六个参数，先弄清各自管什么</h2>
<p>把白名单当成一个开关是最常见的误解。它其实是一张带条件的访问控制表，每一条记录都有作用域和生命周期。</p>
<h3>六个参数的职责划分</h3>
<p>授权类型决定「凭什么放行」，可以是来源 IP、账号口令、还是设备标识；绑定对象决定「放行到哪个环境」；生效延迟决定「改完多久起作用」；条数上限决定「能加几条」；回收方式决定「失效后是拒绝还是转备用」；日志留存决定「出问题能不能查」。六项里前两项影响能不能用，后四项影响好不好用。</p>
<h3>先确认你的方案是哪一种</h3>
<p>市面上常见两类：一类把白名单做在代理入口，只有名单内来源能连；一类做在账号维度，名单内设备免二次验证。两者配置位置不同，排查路径也不同，动手前先在文档里确认，别照着别人的截图配。</p>

<h2>二、授权类型与绑定对象：决定能不能用</h2>
<p>这两项是白名单的核心，配错就是彻底不通，症状明显但也最费时间。</p>
<h3>来源 IP 型的取值与陷阱</h3>
<p>填的是发起访问那一端的公网出口 IP，不是内网地址。办公室宽带若是动态 IP，重启光猫后地址会变，白名单立刻失效。这种场景要么申请固定 IP，要么把授权类型换成口令型。判断办法：在办公机上访问 <code>https://ipinfo.io/ip</code>，隔天再访问一次，两次不同就说明是动态。</p>
<p>另一种授权类型是口令型，适用面不同：口令型不依赖来源地址，适合远程办公、多地协作。代价是口令泄露即失守，需要配合定期轮换和最小权限。团队规模超过五人时，建议一人一条口令，而不是共用一个，这样撤销时只影响一个人。</p>
<h3>绑定对象要精确到环境</h3>
<p>一条授权绑定的是「整个账号」还是「某个具体环境」，差别很大。绑定到账号时，名单内设备可以访问该账号下所有环境，权限过宽；绑定到环境时，换人接手只需给新环境加授权，不动其他环境。这就是「不用整号重搭」的技术前提。</p>

<h2>三、生效延迟、条数上限与日志：决定好不好用</h2>
<img src="/tp.png" alt="Claude住宅IP白名单后台添加环境级授权界面">
<p>这三项不影响能不能连上，但直接影响排障效率和协作体验。</p>
<h3>生效延迟要留出余量</h3>
<p>后台显示「已保存」不等于已下发，多数方案有一分钟左右的同步间隔，跨区域节点可能到五分钟。验证方法是保存后等两分钟再发起连接，若此时才通，说明延迟在这个量级。排障时若在保存后十秒就测，很容易误判成配置错误，然后去改本来正确的设置。</p>
<h3>条数上限会被静默忽略</h3>
<p>名单满额后再添加，部分后台不报错，只是新记录不生效。症状是「明明加了却没放行」。做法是定期清理已离职成员的授权，保持名单在三到五条以内，别让它长期贴着上限跑。</p>
<h3>日志要看三个字段</h3>
<p>命中时间、来源标识、结果（放行或拒绝）。三个字段能回答绝大多数问题：谁在什么时候用什么身份访问了什么。留存建议至少三十天，团队协作场景下这是划分责任的基础。</p>

<h2>四、换人接手时的标准操作顺序</h2>
<p>这一节是实操。目标是在不动原环境的前提下，把访问权平稳交出去。</p>
<h3>五步顺序不能乱</h3>
<p>第一步，先给接手人建独立身份（口令或设备），不要共用离职同事的；第二步，在环境级授权里追加一条，指向新身份，保留旧授权不动；第三步，等生效延迟过去，让接手人实测连通性与出口类型；第四步，确认可用后，再撤销旧授权；第五步，把变更时间、变更人、涉及环境写进台账。</p>
<h3>为什么先加后删</h3>
<p>反过来做会有一段无人可用的空窗，一旦新授权配错，还得回滚。先加后删的最坏情况是两条授权并存几分钟，风险远小于断线。</p>
<p>换人时不要动环境本身：浏览器配置、出口地址、时区语言都不需要改。这些是账号侧的特征，动它们等于制造一次环境跳变，比换人本身的风险大得多。这正是「加一条授权即可」的价值所在。</p>

<h2>五、三种常见误配与对应症状</h2>
<p>把症状和参数对上，排查就不用猜。</p>
<h3>能连但频繁要求验证</h3>
<p>多半是授权绑定到了账号级，导致多个来源共用同一授权，平台侧看到同一环境多来源访问。改成环境级、一人一条，症状通常会缓解。</p>
<h3>改完立刻不通，过几分钟又通了</h3>
<p>典型的生效延迟。不需要改任何配置，等两到五分钟即可。若十分钟仍不通，再查来源标识是否填错。</p>
<h3>新增授权后台显示成功但不生效</h3>
<p>先看名单条数是否已满。满额时部分后台静默丢弃新记录，清理无用条目后重新添加即可。</p>

<h2>常见问答</h2>
<h3>白名单能不能同时用 IP 和口令两种？</h3>
<p>答：部分方案支持组合，满足任一条件即放行，安全性取决于较弱的那个。若安全要求高，建议只用一种并配合定期轮换，组合使用的规则要在文档里写清，否则排障时会互相干扰。</p>
<h3>团队成员离职后要立刻删授权吗？</h3>
<p>答：要，但建议在交接完成后删。顺序是先给接手人加授权、验证可用，再撤离职成员，中间不要留空窗。删除后记得同步更新台账，避免下次排查时对不上。</p>
<h3>白名单条数不够用怎么办？</h3>
<p>答：优先做粒度优化，而不是加条数。把临时授权回收、按环境而非按人授权、共用场景改成口令型，通常能在原上限内解决。确实不够时再向服务商申请提额。</p>
<h3>加了白名单还需要改密码吗？</h3>
<p>答：建议定期改。白名单控制的是「谁能连」，口令控制的是「拿什么连」，两者是不同层。人员变动时两件事都做，才算完整交接。</p>
